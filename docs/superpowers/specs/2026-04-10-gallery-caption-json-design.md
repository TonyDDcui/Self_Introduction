# Gallery 配文：严格 JSON 输出（无 thinking）Design

日期：2026-04-10

## 背景 / 问题

当前 EdgeFn + DeepSeek-R1 系列模型经常输出 **thinking/过程文**（例如“用户让我…”），甚至把最终内容放在 `reasoning_*` 字段或 `<think>...</think>` 中，导致：
- 前端展示出现“割裂感强”的过程文
- 解析/清洗逻辑不断堆叠，代码变复杂，仍不稳定

## 目标

1. 配文展示 **只出现最终配文正文**（优美、文学感、流畅），不出现 thinking/过程文。
2. 在没有标题/描述/标签时，仍能根据“相册主题”生成一段合理配文（不解释推测过程）。
3. **成功率优先**：如果模型输出不合规，允许自动重试一次；仍失败则明确提示并允许管理员重新生成。
4. 删除当前复杂、繁琐且不稳定的清洗/兜底逻辑，改成更可维护的方案。

## 方案（推荐：严格 JSON）

### 输出契约

所有“照片配文”生成统一要求模型 **只输出严格 JSON**：

```json
{"caption":"这里是最终配文正文"}
```

任何非 JSON 内容都视为无效输出，不会展示到页面。

### Prompt 策略

- 系统提示强调：不要 thinking、不输出解释，只输出 JSON。
- 用户提示包含：标签/标题/描述 + 相册主题（由 `classifyAlbumFromPhoto()` 推断的相册 title + themeTags）。
- 当标题/描述/标签均为空：让模型基于相册主题词“想象一个合理场景”写文学配文，但仍只输出 JSON，不解释推测过程。

### 解析/校验

服务端收到模型文本后：
- 只做最小解析：从文本中抽出 `{...}` 并 `JSON.parse`
- 只接受 `caption` 字段（string）
- 校验：单行、长度合理（<= 80），不得包含 `<think>`/“用户/要求/分析/思考”等过程词
- 失败则重试一次（加强提示 + 给出示例 JSON）
- 仍失败：返回 `AI_CAPTION_INVALID_OUTPUT`

### 影响范围

- 初次生成：`src/lib/gallery/photoNarratives.ts`
- 管理员“重新生成配文”：`app/api/gallery/photos/[id]/narrative/regenerate/route.ts`

## 验收标准

1. Gallery 页面与相册页展示的配文不包含 thinking/过程文。
2. 没有标题/描述/标签的图片也能生成流畅、文学化的配文（或最差给出可重试错误，不展示过程文）。
3. 代码层面：删除之前复杂的“提取最后一行/按句切分”等兜底逻辑，只保留 JSON 解析 + 简单校验。
